# راهنمای مهاجرت به نسخه 0.2.0

این نسخه مرحله اول پایداری Note Maker را تکمیل می‌کند. مهم‌ترین تغییر رفتاری آن این است که وجود یک فایل خروجی به‌تنهایی دیگر دلیل کافی برای Skip شدن Job نیست؛ وضعیت هر Job در Manifest ثبت و اعتبارسنجی می‌شود.

## 1. پیش از ارتقا

1. از پوشه‌های `outputs/`، `logs/` و Promptهای سفارشی نسخه پشتیبان بگیرید.
2. اگر اجرای فعالی وجود دارد، آن را متوقف کنید و Chrome مربوط به Profile پروژه را ببندید.
3. وابستگی‌ها را دوباره نصب یا به‌روزرسانی کنید:

```bash
./setup.sh
```

4. تست‌ها و پذیرش مرورگر-آزاد را اجرا کنید:

```bash
./run_tests.sh
./run_phase1_acceptance.sh
```

## 2. خروجی‌های قدیمی بدون Manifest

به‌صورت پیش‌فرض، فایل خروجی قدیمی که در `manifest.json` ثبت نشده است قابل اعتماد تلقی نمی‌شود و دوباره ساخته خواهد شد. برای ثبت خروجی‌های فعلی بدون بازکردن ChatGPT از گزینه زیر استفاده کنید:

```bash
./run_pdf_to_notes.sh --adopt-existing
```

این گزینه:

- خروجی موجود را اعتبارسنجی می‌کند؛
- فقط فایل معتبر را با وضعیت `completed` ثبت می‌کند؛
- `output_hash` را محاسبه می‌کند؛
- مقدار `adopted: true` را در Manifest قرار می‌دهد؛
- فایل نامعتبر را Adopt نمی‌کند.

محدودیت: سازگاری تاریخی فایل Adoptشده با Prompt قبلی قابل اثبات نیست. پس از ثبت، تغییر Source یا Prompt جدید باعث اجرای مجدد خواهد شد.

## 3. رفتار Resume

مسیر پیش‌فرض:

```text
<output-dir>/manifest.json
```

اجرای بدون تغییر:

```bash
./run_pdf_to_notes.sh
```

Jobهای Completed که Hash و Validation آن‌ها صحیح است Skip می‌شوند و اگر همه Jobها قابل Skip باشند Browser باز نمی‌شود.

اجرای فقط موارد شکست‌خورده یا قطع‌شده:

```bash
./run_pdf_to_notes.sh --retry-failed
```

اجرای مجدد همه موارد انتخاب‌شده، بدون استفاده از تصمیم Resume:

```bash
./run_pdf_to_notes.sh --no-resume
```

بازسازی صریح تمام خروجی‌ها:

```bash
./run_pdf_to_notes.sh --overwrite
```

اولویت `--overwrite` از Resume بالاتر است.

## 4. خروجی نامعتبر

Artifact جدید ابتدا با نام موقت وارد پوشه خروجی می‌شود. فقط پس از Validation با `os.replace` جایگزین خروجی اصلی خواهد شد.

در صورت رد شدن:

```text
<output-dir>/_rejected/<name>-<timestamp>.<ext>
```

خروجی سالم قبلی حذف یا بازنویسی نمی‌شود.

Markdown باید حداقل H1، H2 و محتوای واقعی داشته باشد. OPML باید قابل Parse باشد و `body` و حداقل یک `outline` داشته باشد.

## 5. Diagnostics

شکست نهایی همیشه در مسیر زیر ذخیره می‌شود:

```text
<output-dir>/diagnostics/<run-id>/<job>/
```

محتوا می‌تواند شامل موارد زیر باشد:

- `metadata.json`
- `last_response.txt`
- `last_state.png`
- `validation_errors.json`
- Artifact ردشده

برای ذخیره Retryهای میانی:

```bash
./run_pdf_to_notes.sh --save-diagnostics
```

ذخیره Page Source فقط در عیب‌یابی ضروری توصیه می‌شود:

```bash
./run_pdf_to_notes.sh --save-page-source
```

این فایل ممکن است اطلاعات حساس Session را در خود داشته باشد.

## 6. Exit Codeها

| کد | معنی |
|---:|---|
| `0` | تمام Jobهای لازم موفق شدند یا معتبر Skip شدند |
| `1` | خطای کلی مانند پیکربندی، مسیر یا Dependency |
| `2` | حداقل یک Job یا تبدیل PDF ناموفق بود |

اسکریپت‌های Shell با `set -e` پس از کد `2` متوقف می‌شوند؛ بنابراین PDF ترکیبی ناقص ساخته نمی‌شود.

## 7. PDFهای قدیمی

پیش از ادغام، PDF هر Note بررسی می‌شود:

- اگر PDF وجود نداشته باشد، ساخته می‌شود؛
- اگر Markdown جدیدتر باشد، PDF بازسازی می‌شود؛
- اگر PDF به‌روز باشد، دوباره Render نمی‌شود.

در نسخه 0.2.0 این تصمیم بر اساس `mtime_ns` است.

## 8. بازگشت اضطراری

در صورت بروز مشکل در Resume، بدون حذف Manifest از این دستور استفاده کنید:

```bash
./run_pdf_to_notes.sh --no-resume
```

برای بازگشت کامل، نسخه پشتیبان پروژه و خروجی‌ها را Restore کنید. فایل `manifest.json.bak` نیز آخرین نسخه سالم پیش از نوشتن فعلی را نگه می‌دارد.
